# Project Queen: ฿1,430 P102-100 runs GTA V at 1080p and up to 75 FPS on Windows

**Colten Steele Studios research update — 27 November 2026**

**From mining hardware to a Windows gaming and game-development workstation.** Our ฿1,430 NVIDIA P102-100 10 GB renders GTA V at 1080p with a very-high-to-ultra-oriented graphics mix, reaching an owner-observed 70–75 FPS, while a GT 1030 drives the monitor. The same Windows machine also runs our original Godot city. No Linux boot was needed for these Windows results. This particular integration is our documented achievement; global first status has not been established.

## Reversible Gen2 operation on Windows

A particularly useful milestone is the documented stop/reactivate sequence without a system reboot. Before stopping the community utility, both PCIe endpoint and root-port readback showed Gen2 x4 (endpoint LNKSTA 0x1042). After stopping it, five pinned CUDA transfers returned to approximately Gen1 throughput. Reactivating the original utility path restored higher throughput across five consecutive pinned trials.

| State | Median H2D (GB/s) | Median D2H (GB/s) |
|---|---:|---:|
| After stop | 0.797 | 0.841 |
| After reactivation | 1.546 | 1.680 |

Integrity checks passed in both states. The post-stop physical link was not separately read back in this evidence set, so the lower speed is a transfer observation, not an independent register proof. This is a potentially distinctive Windows integration and a useful recovery feature; global precedence has not been established. A logon-start registration was recorded, but automatic recovery across a fresh reboot with successful game rendering and Gen2 measurements is a separate acceptance test. We will not claim that until the complete evidence is recorded.

## Windows graphics research

The preserved 1080p configuration uses a very-high/ultra-oriented graphics mix, with FXAA enabled, 16× anisotropic filtering, MSAA disabled, 50% distance scaling and 40% population density. Advanced ultra shadows are disabled. This is not an all-max-settings or MSAA benchmark.

The native D3D11 probe passed on the GT 1030 but failed on the P102. Our game-local DXVK 2.6.2 experiment achieved working Vulkan rendering on the P102 while the GT 1030 drove the monitor. No Windows system DLL replacement was used. A two-frame DXVK queue limit was the latest performance experiment; VSync remained disabled and graphics settings were unchanged during that comparison. Owner observations improved from roughly 60–65 to 70–75 FPS; the route was not controlled, so this is not a quantified causal speedup. Both installed display-driver packages and the working launch configuration have been archived privately for recovery.

## Reproduce the Windows dual-GPU approach

Start with a supported Windows installation, a legitimate copy of your game, a display-capable adapter and a separate compute/mining card. This is a staged compatibility checklist, not a universal unlock installer.

1. Connect the monitor to the display-capable card. Record each GPU model, VRAM capacity, hardware ID, installed driver package and cooling state. Queen uses a P102-100 plus GT 1030 and NVIDIA 582.78.
2. Back up the existing driver packages and game settings, and verify both adapters initialize normally. Obtain compatible drivers from their original sources; do not assume our adapted P102 package supports other mining cards.
3. Verify that the mining GPU can render a native Vulkan application, independently of the display card. Check actual renderer identity and adapter-specific GPU activity rather than relying on Windows display names alone.
4. Test the game's native API first. For compatible offline Direct3D games, investigate [upstream DXVK 2.6.2](https://github.com/doitsujin/dxvk/releases/tag/v2.6.2) in an isolated game directory. Keep all system DLLs untouched. Queen's GTA V installation required an additional game-specific library-loading compatibility fix; this is not yet a portable installer.
5. The known Queen launch environment selects the mining renderer with `DXVK_FILTER_DEVICE_NAME=P102` and sets `DXVK_FRAME_RATE=0` for uncapped testing. The game-local configuration uses `dxgi.maxFrameLatency = 2` as an experimental setting; compare against defaults before retaining it. These settings alone do not reproduce the driver or library-loading fix.
6. Record the selected render GPU, monitor adapter, temperatures, power, FPS and frame times. Compare identical scenes and graphics settings, then repeat after restart. Stop if the machine becomes unstable. Do not extrapolate Queen's result to another GPU or driver revision without testing.

For another mining card, substitute its actual device name and verify compatibility independently. Our P104 and CMP 70HX research notes document separate hardware experiments, not interchangeable Windows installation procedures. We plan a downloadable compatibility toolkit with version checks, recovery instructions and independently verified configurations; this checklist is the first documentation step, not a released toolkit.
